# Changelog

## Unreleased

## 0.1.8

- CI: убрана проверка `FromContext(nil)` в тесте request-id — `go tool staticcheck` (SA1012) не читает `//nolint` и валил workflow 0.1.7.
- Безопасность: `X-Forwarded-Proto` учитывается только от адресов из `TRUSTED_PROXIES` (как уже было для `X-Forwarded-For`/`X-Forwarded-Host`). Раньше прямой клиент мог прислать `X-Forwarded-Proto: https` по plain HTTP и получить cookie с флагом `Secure`, которую браузер по HTTP отбрасывает (бесконечный логин), а также обмануть любую логику «соединение защищено».
- Запуск: `AUTH_TOKEN=dev-token` (значение из `.env.example`) больше не принимается — сервис не стартует с подсказкой; для локальной разработки `ALLOW_DEV_TOKEN=true`. В `.env.example` токен теперь пустой. Причина: этот токен аутентифицирует как первого пользователя с правами admin, и скопированный пример становился боевым паролем.
- `go.mod`: `toolchain go1.27.1` — релизы и CI собираются тем же патч-релизом Go, что и разработка (раньше setup-go брал `go 1.27.0` и релиз 0.1.7 был собран более старым toolchain, чем тестировался).
- Ленты: журнал опросов (`feed_poll_log`, миграция 0032) — по строке на каждую попытку (время, ок/ошибка, сколько новых записей, длительность, текст ошибки). Последние 30 показываются в Админка → Состояние лент → лента; срок хранения `FEED_POLL_LOG_RETENTION_DAYS` (по умолчанию 14, 0 — не удалять) чистится той же автоочисткой и редактируется на странице «Система». Раньше после успешного опроса след ошибки исчезал (`last_error` перезаписывался), и ответить «почему лента вчера встала на автостоп» было нечем.
- Ленты: после неудачного опроса `next_check_at` выставляет сам refresher (та же формула backoff, что у воркера), поэтому `jobs.run_at` и `feeds.next_check_at` совпадают, а ручное обновление из UI/API при ошибке тоже откладывает следующий опрос.
- WebSocket: событие `feed_status_changed` несёт реальное состояние ленты после опроса — `parsing_error_count`, `poll_paused`, `manual_paused`, `next_check_at`, `last_checked_at`, `parsing_error_message` (раньше счётчик был захардкожен 0/1). Боковая панель UI перекрашивает строку ленты (⚠/▸, подсказка с ошибкой) без перезагрузки.
- Конфигурация: `FILTER_MATCH_RETENTION_DAYS=0` теперь действительно отключает очистку совпадений фильтров (раньше «0» молча заменялся на значение по умолчанию 90).
- OPML: экспорт содержит настройки лент в атрибутах `rssam:*` (`feedType`, `interval`, `tlsInsecure`, `fetchViaProxy`, `crawler`, `hashOnly`, `retentionDays`, `userAgent`, `webhook` по имени, правила scraper/rewrite/blocked/keep); импорт восстанавливает их с валидацией (некорректные значения и неизвестные/неоднозначные имена вебхуков попадают в отчёт, лента при этом создаётся с настройками по умолчанию). Раньше при экспорте всё это терялось. Замечания импорта теперь показываются и в UI.
- Вебхуки: счётчики «Отправлено» / «Недоставлено» / последняя ошибка хранятся в самой записи webhook (миграция 0031, с переносом из существующих логов) и больше не обнуляются при очистке журнала доставки по сроку хранения; сброс — только кнопкой «Сбросить счётчики» на странице webhook.
- Вебхуки: статус «Мёртвые» переименован в «Ошибки» и означает «последняя доставка не удалась»; успешная доставка после ошибки возвращает статус «В норме». Фильтр `?status=dead` заменён на `?status=error`.
- Фильтры: действие «Удалить запись» снова работает — оно использовало `BulkUpdateEntries`, который по контракту отвергает статус `removed` (защита пользовательского bulk-API), поэтому запись оставалась непрочитанной. Добавлен `MarkEntriesRemoved` для внутреннего soft-delete.
- Тесты: сквозной прогон `poll → фильтры → webhook` на реальном PostgreSQL (`internal/e2e`, тег `integration`, в CI вместе со storage-тестами): доставка по привязке к ленте с body_template/HMAC/заголовками и `on_success_entry`, повтор без дублей, `5xx → backoff → error` и восстановление после ручного retry, метки/webhook/удаление из фильтров, очистка журнала без потери счётчиков.
- Админка → Система: настройки сроков хранения (`REMOVED_RETENTION_DAYS`, `WEBHOOK_LOG_RETENTION_DAYS`, `FILTER_MATCH_RETENTION_DAYS`, `CLEANUP_INTERVAL`) редактируются из UI (пишутся в `.env`, применяются после перезапуска) и кнопка «Очистить сейчас».

## 0.1.7

- CI: golangci-lint v2 в workflow, staticcheck/govulncheck через `tool` в `go.mod`, Dependabot, actions по SHA.
- Безопасность: редиректы UI только на путь `/ui/` (Referer/`next`); цвета категорий/меток — только `#hex`; логи вебхуков и retry проверяют владельца; правила фильтра валидируются при записи (не компилируемый regex → 400).
- Админка: «Перезапустить сервис» больше не отвечает 400 из‑за SIGTERM дочернему `sudo`; `ops.Restart` считает такой сигнал штатным.
- `install.sh`: arm64, проверка SHA256SUMS (без суммы — отказ). Два systemd‑юнита: обычный (с самообновлением из UI) и hardened (opt-in).
- API: полный OpenAPI‑контракт + тест паритета роутов; `X-Request-Id` в ответе, логах и JSON 5xx.
- Рефакторинг: `server.go` разнесён по областям, `go fix`; быстрые тесты (bcrypt MinCost в TestMain), fuzz, k6‑профиль.

## 0.1.6

- Go 1.27; pgx 5.10 (CVE-2026-33815/-33816, CVE-2026-41889), x/crypto 0.56, gofeed 1.4.2; `govulncheck` в CI.
- Безопасность: HTML записей санитизируется для всех источников (раньше — только RSS; Telegram-мост копировал разметку t.me как есть); отдельный лимит на `POST /ui/login` (`LOGIN_RATE_LIMIT_RPS`/`_BURST`, по умолчанию 10 попыток, затем 1 в 5 с); версия для self-update — только semver-тег (в UI и `install.sh`); убран `/docs` (Swagger UI с unpkg.com, не работал под собственной CSP); входящие WebSocket-кадры до 16 KiB; `AUTH_TOKEN` сравнивается за постоянное время.
- Нельзя удалить последнего администратора с паролем (`DELETE /v1/users/{id}` → 409, UI → 409); раньше инстанс можно было оставить без входа в UI.
- README: раздел «Публикация в интернете».
- Комментарии: убрана история изменений из комментариев кода (что «раньше было») — остались только текущие инварианты и причины.

## 0.1.5

- Безопасность: same-origin для cookie-запросов к `/v1` (мутации) и `/ws/v1`; SSRF-guard блокирует multicast/reserved и IPv4 внутри NAT64/6to4; логин с одинаковым временем ответа для неизвестного пользователя; пароль 8–72 (сервер, не только форма); служебные заголовки вебхуков не переопределяются.
- Производительность: `UPDATE sessions` не чаще раза в час; просроченные сессии удаляются cleanup'ом (миграция 0030); кэш вебхуков на пути refresh.

## 0.1.4

- Retention cleanup: типизация `$1::timestamptz` и удаление `feed_entry_dedup` по `(feed_id, hash)` — чистка снова выполняется.
- Свежая установка: `ADMIN_USERNAME`/`ADMIN_PASSWORD` пишутся на placeholder `users.id=1` (логин UI и `AUTH_TOKEN` — один тенант).
- WebSocket: Hijack через access-log, события только владельцу ленты, `subscribe`/reconnect в UI.
- Rate-limit: `TRUSTED_PROXIES` (по умолчанию loopback); чужой `X-Forwarded-For` игнорируется.
- RSS/Atom: лимит тела 16 MiB. Смена пароля требует текущий и отзывает прочие сессии. API-токен не в URL.
- Миграции под `pg_advisory_lock`. CI: `-race`, staticcheck, Postgres integration и smoke логина на отдельной БД.

## 0.1.3

## 0.1.2

- CSRF: если нет AUTH_TOKEN/METRICS_TOKEN, генерируется CSRF_SECRET и пишется в .env.
- API-токен больше не принимается из query string (`?token=`); только заголовок или сессия. WebSocket в UI по-прежнему через cookie.
- Retry вебхуков: потокобезопасный jitter, без panic на крошечных интервалах.
- Rate limit: вытеснение неактивных IP и потолок размера карты.
- Cleanup retention: удаление батчами, без одной длинной транзакции.
- Поиск: не роняет весь UI («search failed»); `plainto_tsquery` вместо `websearch_to_tsquery`.
